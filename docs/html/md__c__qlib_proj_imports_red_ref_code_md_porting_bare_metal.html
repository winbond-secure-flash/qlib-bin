QLIB User-Guide
Bare Metal (No OS or Simple Scheduler)

Hardware Abstraction:

Direct register access. Reading/writing directly to the micro controller's SPI peripheral registers (e.g., Control Register, Status Register, Data Register). You'll need the microcontroller's datasheet and reference manual.

Implementation:

  • Manually control the Chip Select (CS) GPIO pin: Set it low before starting, set it high after completion.
  • Configure SPI parameters (mode specified by format, clock speed, etc.) by writing to control registers.
  • Implement the sequence step-by-step:
    • Write command bytes: Loop cmdSize times, writing a byte to the SPI Data Register and waiting for the transmit buffer empty flag (or transmit complete flag) in the Status Register. Read the Data Register to clear the receive flag if necessary, even if ignoring the received data during write.
    • Write address bytes: Similar loop for addressSize.
    • Write data bytes: Similar loop for dataOutSize.
    • Dummy cycles: Loop dummyCycles times, writing a dummy byte (e.g., 0x00 or 0xFF) and waiting for completion, discarding received data.
    • Read data bytes: Loop dataInSize times, writing a dummy byte, waiting for the receive buffer full flag, and reading the received byte into the dataIn buffer.
  • The userData pointer might hold a pointer to a struct containing base addresses of SPI peripherals, GPIO pin configurations for CS, etc.

Concurrency:

Simple. Usually single-threaded. If interrupts are used, critical sections accessing SPI registers or controlling CS might need to be protected by disabling/enabling interrupts briefly.

Blocking:

The implementation will be inherently blocking, relying on polling status flags in loops (busy-waiting).

Atomicity:

Achieved by manually keeping CS low for the entire duration.

Error Handling:

Check SPI status register flags (e.g., over run, under run, mode fault) after operations and return appropriate error codes.
