QLIB User-Guide
Linux (User Space)

Hardware Abstraction:

Interacts with the kernel's SPI subsystem, typically via the spidev driver. This exposes SPI devices as character device files in /dev/ (e.g., /dev/spidevB.C). Interaction is done using file operations: open, close, ioctl, read, write.

Implementation:

  • Mutual Exclusion: Primarily handled by the kernel. While multiple processes can open the device, the kernel typically serializes ioctl transfer requests for that specific chip select. Application-level locking might be needed if multiple threads within the same process access the same file descriptor concurrently, though often a single thread manages the SPI device.
  • Transaction: The key is the ioctl(fd, SPI_IOC_MESSAGE(N), struct spi_ioc_transfer *xfers) system call. This allows sending an array of N transfer structures (spi_ioc_transfer) in a single atomic operation (kernel keeps CS# asserted for the duration of the array processing unless cs_change is specified).
    • Single transaction approach:
      • tx_buf: Point to dataOutStream (which must contain cmd+addr+data contiguously).
      • rx_buf: Point to dataIn.
      • len: Set to the total length needed for the transaction. This is tricky. Often, it's cmdSize + addressSize + dataOutSize + dummyCycles + dataInSize. The rx_buf will receive valid data only during the final dataInSize bytes of the transfer. The initial bytes received during the TX phases are usually discarded by the application. Set speed_hz, bits_per_word, delay_usecs (can sometimes be used for short delays instead of dummy bytes, but clocking dummies via TX is more common), cs_change = 1 (to deassert CS# after this transfer).
    • Several transactions approach (maybe cleaner):
      • First transfer: tx_buf points to dataOutStream, len is cmdSize + addressSize + dataOutSize + dummyCycles, rx_buf is NULL. cs_change = 0.
      • Second transfer: tx_buf is NULL (or points to dummy TX data), len is dataInSize, rx_buf points to dataIn. cs_change = 1.
    • Configure mode (SPI_MODE_0..3), LSB/MSB, bits per word, max speed using separate ioctl calls (SPI_IOC_WR_MODE, SPI_IOC_WR_LSB_FIRST, SPI_IOC_WR_BITS_PER_WORD, SPI_IOC_WR_MAX_SPEED_HZ) after opening the device and before the SPI_IOC_MESSAGE call. Some can be overridden per-transfer in spi_ioc_transfer. Map format and flags to these ioctls.
  • The userData would most likely contain the file descriptor (int fd) returned by open("/dev/spidevB.C", O_RDWR).

Concurrency:

Handled by the kernel's scheduling and locking for spidev.

Blocking:

The ioctl(SPI_IOC_MESSAGE(...)) call is blocking. The user-space process sleeps until the kernel driver completes the entire sequence (potentially using DMA/interrupts internally).

Atomicity:

Ensured by the SPI_IOC_MESSAGE ioctl processing multiple transfers before deasserting CS# (unless cs_change directs otherwise).

Error Handling:

open, ioctl, read, write return -1 on error and set the errno variable. Check errno and translate Linux error codes (e.g., EINVAL, EIO, ETIMEDOUT) to your library's error codes.
