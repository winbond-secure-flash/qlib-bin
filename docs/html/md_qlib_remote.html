QLIB remote

QLIB can run on a server and communicate with one or more remote clients. Each client has its own QLIB instance. To reduce latency and network traffic, the TM layer handles communication between the server and each client.

Each QLIB instance exposes the standard QLIB API. The client and server must implement their communication in the TM layer.

Because the server is not connected directly to W77Q/T, it must not call QLIB_InitDevice. Only the client may call this function.

To synchronize the QLIB instances, the client must call QLIB_ExportState and send the resulting QLIB_SYNC_OBJ_T to the server. The server must then call QLIB_ImportState with that object.
