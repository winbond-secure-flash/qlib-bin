QLIB remote

QLIB can run on a server, and communicate with a remote client(s). Each client has its own instance of QLIB.
In order to reduce delay and network traffic, the communication between the server and the client is handled in the TM layer.

Each instance of QLIB has the standard QLIB API. In addition, the client and the sever should implement the communication between them, in the TM layer.

Since the server is not connected directly to the W77Q/T, it shouldn't run QLIB_InitDevice.
Only the client should run QLIB_InitDevice.

The client should also run QLIB_ExportState, send the QLIB_SYNC_OBJ_T to the server, and the server then should run QLIB_ImportState using that object.
This will ensure that both instances of Qlib are working with the same configurations.
