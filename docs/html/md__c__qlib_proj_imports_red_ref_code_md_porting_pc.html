PC + FTDI ft4222h USB SPI chip + LibFT4222 library

The ft4222h-based setup is widely used way to interface spi devices using PC.

Hardware Abstraction:

  • Driver: Requires the standard FTDI D2XX drivers installed on the PC. LibFT4222 acts as a layer on top of D2XX.
  • Library: Uses LibFT4222.dll (Windows) or libft4222.so (Linux). You'll link against it and include the LibFT4222.h header.
  • Device Identification: The library provides functions like FT4222_GetDeviceList and FT4222_OpenBy* (e.g., FT4222_OpenByDescription, FT4222_OpenByIndex) to find and open the FT4222H device.
  • Chip Functionality: The FT4222H chip has dedicated modes (SPI Master/Slave, I2C Master/Slave, GPIO). LibFT4222 configures the chip mode and provides functions specific to that mode.

Implementation:

  • Initialization:
    • Find the FT4222H device(s) using FT4222_GetDeviceList or similar.
    • Open the desired device using FT4222_OpenBy* to get an FT_HANDLE.
    • Initialize the chip for SPI Master mode using FT4222_SPIMaster_Init. This function is crucial as it configures:
      • SPI clock speed (clkDiv - clock divisor).
      • Clock Polarity and Phase (cpol, cpha) - derived from your format parameter.
      • Slave Select (CS) line (ssoMap) - maps which of the dedicated SS0-SS3 pins will be used.
      • I/O mode (single, dual, quad - usually single for generic SPI flash).
  • userData: This pointer should contain the FT_HANDLE obtained from FT4222_OpenBy*. It might also wrap other context if needed, but the handle is the primary requirement.
  • Transaction (The Core Task): LibFT4222 provides functions tailored for SPI master operations. The most suitable function for your requirement is likely FT4222_SPIMaster_MultiReadWrite. This function is specifically designed for transactions involving writing some bytes followed immediately by reading some bytes, which is common for SPI flash operations (command -> address -> dummy -> read).
    • Prepare Buffers: You'll need the dataOutStream (containing command + address + data) and the dataIn buffer.
    • Dummy Bits Handling: Calculate the number of dummy bytes: num_dummy_bytes = (dummyCycles + 7) / 8;
    • Call FT4222_SPIMaster_MultiReadWrite:
      • Pass the FT_HANDLE.
      • Pass the dataIn buffer pointer (singleReadBuffer).
      • Pass the dataOutStream buffer pointer (singleWriteBuffer).
      • Specify the total number of bytes to write initially: writeSize = cmdSize + addressSize + dataOutSize.
      • Specify the number of dummy bytes to insert: multiChipReadDummyBytes = num_dummy_bytes.
      • Specify the number of bytes to read finally: sizeOfRead = dataInSize.
      • Set isEndTransaction to true to de-assert CS after the read, unless PLAT_SPI_FLAG_KEEP_CS_ASSERTED is set.
    • Chip Select (CS) Management: The FT4222_SPIMaster_MultiReadWrite function (and other FT4222_SPIMaster_* functions) automatically handles the assertion and de-assertion of the Chip Select line configured during FT4222_SPIMaster_Init. You do not typically need manual GPIO control for CS when using these SPI master functions. The function ensures CS stays asserted throughout the write, dummy, and read phases defined in its parameters.
    • Cleanup: Call FT4222_UnInitialize (if needed to change modes) and FT4222_Close to release the device handle when done.
  • Concurrency:
    • The underlying D2XX calls and USB communication require serialized access. If multiple threads need to use the same FT4222H device via the same handle, you must implement external locking (OS mutexes) around calls to LibFT4222 functions, especially around the FT4222_SPIMaster_MultiReadWrite call or any sequence that needs to be atomic.
  • Blocking:
  • LibFT4222 functions involved in device communication (FT4222_OpenBy*, FT4222_SPIMaster_Init, FT4222_SPIMaster_MultiReadWrite, FT4222_Close, etc.) are blocking. They wait for the USB transaction to complete and the FT4222H chip to respond, or until an internal timeout occurs. Your PLAT_SPI_WriteReadTransaction implementation will be inherently blocking.
  • Atomicity:
    • Atomicity is primarily handled automatically by the FT4222_SPIMaster_MultiReadWrite function. It performs the entire sequence (write specified bytes, clock dummy bytes, read specified bytes) while keeping the selected CS line asserted. This is a significant advantage over libMPSSE where manual CS control is often required for multi-part transactions.
  • Error Handling:
    • LibFT4222 functions return an FT4222_STATUS code (an enum). FT4222_OK (value 0) indicates success.
