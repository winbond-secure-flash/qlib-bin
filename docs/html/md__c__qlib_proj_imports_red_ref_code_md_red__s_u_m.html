[SUM] Secure update mechanism

W77Q provides the fundamental contribution to the device SUM with its atomic fw update feature.

The idea behind fw feature update is simple: it is done over rollback section which is split into two halves - active and inactive. New section content (new fw) is written to the inactive part of the section and when the writing is over, cryptographically protected swap command is issued and these halves swap in one atomic operation. Such way enables user to write/download new fw slowly in low power state, while actual update is completed immediately. This command can be cryptographically protected with both symmetric and asymmetric crypto.

Symmetric cryptography based

This is when section configuration command is issued during secure session with the device. So it is just a encrypted spi transaction sent from the local or remote host to the connected W77Q target.

Asymmetric cryptography based

This is a bit different - now no secure session to W77Q required. Host produces ( maybe offline! ) a section configuration string and signes it with the private part of LMS keypair. Section configuration string is then sent with its signature to the W77Q. W77Q uses public part of the LMS keypair to verify the section configuration string and if successful W77Q will execute this configuration command accordingly.

Benefits/Drawbacks

Symmetric cypher needs secure session established to the device. This means that each update flow will be different from device to device. On the other hand, key generation for symmetric key is very simple (hkdf function).

Asymmetric cypher does not need session to the device and actually enables you to send "broadcast update", which is signed by private key section configuration string. On the other hand , key generation of asymmetric key-pair is more complex.

C code implementation

SUM implementation is split in two phases - manufacture and field for both symmetric and asymmetric methods. During manufacture flash is configured with required layout and policy - note that for symmetric method we configure shared keys whereas for asymmetric method only public lms key is configured. In this example we configure rollback section and see how fw can be updated via symmetric and asymmetric methods accordingly.
