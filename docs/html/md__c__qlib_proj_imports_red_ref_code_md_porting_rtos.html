Hardware Abstraction:

Typically uses a vendor-provided Hardware Abstraction Layer (HAL) or driver library (e.g., STM32 HAL, NXP MCUXpresso SDK, TI DriverLib). These provide functions like HAL_SPI_Transmit(), HAL_SPI_Receive(), HAL_SPI_TransmitReceive().

Implementation:

  • Mutual Exclusion: SPI peripherals are often shared resources. Use an RTOS mutex or semaphore associated with the specific SPI bus/device. Acquire the mutex before the transaction, release it after.
  • Transaction:
    • Ideally, the HAL provides a combined function (HAL_SPI_TransmitReceive) that can handle the entire sequence, or at least a transmit followed by a receive while keeping CS asserted. This is the preferred approach.
    • If not, you might need to call separate transmit and receive functions (HAL_SPI_Transmit for cmd+addr+data+dummies, then HAL_SPI_Receive for dataIn). You'll need to ensure the HAL configuration keeps CS asserted between these calls (some HALs have flags or modes for this). If the HAL doesn't manage CS across calls, you might need to revert to manual GPIO control for CS around the HAL calls, while still using the HAL for data transfer.
    • Map format, flags to HAL configuration settings (e.g., clock speed, CPOL/CPHA). This might involve re-initializing or re-configuring the SPI handle before the transaction if parameters change frequently.
    • The dataOutStream might need to be prepared contiguously (cmd+addr+data). Dummy cycles might be handled by transmitting dummy bytes within the transmit call.
  • The userData likely points to the HAL SPI handle (e.g., SPI_HandleTypeDef* in STM32 HAL) or a custom struct containing the handle and the mutex.

Concurrency:

Managed by the RTOS scheduler and the mutex/semaphore.

Blocking:

HAL functions usually offer blocking modes (which internally might use RTOS delays or wait on semaphores signaled by interrupts/DMA) and non-blocking/DMA modes. For your function's synchronous signature, you'd typically use the blocking HAL call, or trigger a DMA/interrupt-based transfer and then block the calling task (e.g., osSemaphoreAcquire) until a completion callback signals a semaphore.

Atomicity:

Relies on the HAL's capabilities or manual CS control combined with HAL calls, all protected by the mutex.

Error Handling:

Translate HAL return status codes (e.g., HAL_OK, HAL_ERROR, HAL_TIMEOUT) to your library's error codes.
