IEC 62443 code reference for W77Q Secure flash

The IEC 62443 series of standards define requirements and processes for implementing and maintaining electronically secure Industrial Automation and Control Systems (IACS). These standards set best practices for security and provide a way to assess the level of security performance. Their approach to the cybersecurity challenge is a holistic one, bridging the gap between operations and information technology as well as between process safety and cybersecurity.

Following is IEC 62443 reference with explanations and C code that can be used in your project to simplify IEC 62443 compliance effort. For more details on IEC 62443 compliance see AN0200036. Each requirement contains link to more detailed explanation how it is fulfilled using W77Q devices and ready code snippets for each scenario.

Secure Data Storage / Cryptographic Write Protection

W77Q provides the fundamental contribution to the device its secure storage feature. Secure storage is provided via imposing cryptographically protected policies to the flash sections. After policies and keys are configured, flash access obeys to very certain security rules. Section policy has multiple attributes, each can be used to implement your security architecture.

# plain read/write policy attribute has no keys has restricted key has full access key
1 plain read enabled, plain write enabled read write read write read write
2 plain read enabled, plain write disabled read write read write read write
3 plain read disabled, plain write disabled read write read write read write

Secure Log

W77Q contributes to the device logging as a fundamental feature with its log support.

Log can be protected with different access policies, it can be plain/read only/full access. This stack-like feature can be used to implement different log-related device features for instance:

  • device event log
  • additional rollback protection for securely storing information of previous update ( not necessarily fw ) event.

To use section as log you need to configure it with the log attribute. The idea of log is that log entries can be written (appended to the head of the log ) and read but not erased other then together with the whole section. The rules of log restriction work similar to secure storage ones and depend on the section policy of PA_R ( plain read ) and PA_W ( plain write ).

# PA_R / PA_W section policy has no keys has restricted key has full access key
1 PA_R enabled, PA_W enabled read append erase read write erase read append erase
2 PA_R enabled, PA_W disabled read append erase read append erase read append erase
3 PA_R disabled, PA_W enabled read append erase read append erase read append erase
4 PA_R disabled, PA_W disabled read append erase read append erase read append erase

Secure Firmware Updates using Symmetric / Asymmetric Cryptography

W77Q provides the fundamental contribution with its atomic fw update feature.

The idea behind fw feature update is simple: it is done over rollback section which is split into two halves - active and inactive. New section content (new fw) is written to the inactive part of the section and when the writing is over, cryptographically protected swap command is issued and these halves swap in one atomic operation. Such way enables user to write/download new fw slowly in low power state, while actual update is completed immediately. This command can be cryptographically protected with both symmetric and asymmetric crypto.

Symmetric cryptography based

This is when section configuration command is issued during secure session with the device. So it is just a encrypted spi transaction sent from the local or remote host to the connected W77Q target.

Asymmetric cryptography based

This is a bit different - now no secure session to W77Q required. Host produces ( maybe offline! ) a section configuration string and signes it with the private part of LMS keypair. Section configuration string is then sent with its signature to the W77Q. W77Q uses public part of the LMS keypair to verify the section configuration string and if successful W77Q will execute this configuration command accordingly.

Benefits/Drawbacks

Symmetric cypher needs secure session established to the device. This means that each update flow will be different from device to device. On the other hand, key generation for symmetric key is very simple (hkdf function).

Asymmetric cypher does not need session to the device and actually enables you to send "broadcast update", which is signed by private key section configuration string. On the other hand , key generation of asymmetric key-pair is more complex.

Platform Firmware Resiliency

W77Q provides the fundamental contribution to the device resilience.

Read-only boot memory ( cryptographically write protected boot section )

User can configure boot section to be writable only by authorized user. Other actors can only read from such section. See how to configure such section in secure storage example.

Integrity protected fallback ( remapping boot section upon attack )

If during boot data integrity of the boot section is found to be damaged W77Q will automatically boot section ( aka 0 ) to another one in the flash. So in case of attack on boot section device will boot from another one to the firmware which probably handles attack incident, thus staying available.

C code implementation

RLM code is split in two phases - manufacture and field. During manufacture we make 3 sections and exercise fallback feature. To achieve this we will spoil boot section integrity and see how in this case read from boot section is mapped to fallback section.

section 0 - [ 0 -> 1MB ]

Boot section to be integrity protected ( in picture). Plain read access is enabled, plain write is disabled. Note that we use checksum (crc32) integrity policy, digest (sha256) is also possible.

section 1 - [ 0 -> 2MB ]

This section will overlap section 0 and used as a "hacker window" to spoil integrity of section 0. Both plain read and write access are enabled.

section 7 - [ 2MB -> 3MB ]

This section is to be fallback section to which section 0 access to be mapped if section 0 integrity is corrupt(in picture). This is where you might store your emergency firmware. Both plain read and write access are enabled.

Integrity monitoring ( periodic digest calculation on the section data )

Another way to keep device available is to monitor its integrity. At any moment W77Q can calculate digest (hash function) of flash section so data damage can be detected. Such request can be signed, giving host ( remote or local ) not only the digest value to compare to the expected one but also certainty that this data was provided by W77Q and not spoofed during "man in the middle" attack. In addition, successfully verified signed command can be a basis to the device attestation.

Secure Erase

W77Q contributes is a fundamental feature with its unrecoverable erasure of NOR flash.

Any asset stored in W77Q can be erased, if flash section is write protected by the key, secure erase command authenticated by the same key is used. Format action also deletes content of the chip, including keys configured previously. Format command also has its secure variant which is authenticated by the device master key.

The deletion rules are simple:

  • if section is write protected you will need the same full access key to erase inside this section.
  • read access key is of course not sufficient for erasing the section
  • if chip is configured plain format disabled, master key is needed to format it, otherwise plain command will work.

Winbond Identifier, Secure Unique ID

Each w77q device has its unique identifiers burned during manufacture. All can be read without secure session. These identifiers are:

  • UID - standard flash unique id. Set by Winbond during manufacture, read only, chip format resistant.
  • WID - secure flash unique id. Set by Winbond during manufacture, read only, chip format resistant.
  • SUID - secure user id. Set by user, read/write, chip format erases this field.

Remote Attestation

Direct Attestation

The W77Q/TxxN offers an advanced and direct approach to establish Root-Of-Trust which does not require the participation of the local MCU in the cryptographic operation. This approach is based on the ability of the W77Q/TxxN to “seal” and protect a Section, by verifying its digest and making it Cryptographically Write Protected, and to securely provide the Section status via a Secure Channel to a remote User.

A remote authorized User first establishes a Secure Channel directly with the W77Q/TxxN. Once a Secure Channel is established, the remote User securely reads and authenticates the digest of the firmware that is stored in the Secure Flash Memory. The Secure Channel is based on one of the Master Keys which establishes the hardware identity of the device. The firmware digest establishes the software identity of the device. Together, this process authenticates both the hardware and software identities of the device which is the basis for establishing Root Of Trust.

DICE-Like Device Attestation

The W77Q/TxxN offers hardware functions to support a DICE-like attestation scheme that are used to generate the Compound Device ID. The CDI is based on the Unique Device Secret which establishes the hardware identity of the device and the digest of the firmware which establishes the software identity of the device. These are used to generate the Compound Device ID that authenticates both the hardware and software identities of the device which is the basis for establishing Root Of Trust. This function measures (Hash) the boot-code stored in Section-0 and computes the Compound Device ID. The user can then establish a Session to access Section-0 and securely read the CDI. This operation is allowed only if Section-0 is the only section that was accessed since the last warm reset (including secure and plain access). This assures that the Host running boot code from Section-0 is only given a valid CDI if the boot code integrity is not compromised and no other code was fetched from the Flash.

LMS-OTS based Device Attestation

The W77Q/TxxN offers hardware functions to support an LMS-OTS based attestation scheme. The W77Q/TxxN contains factory provisioned LMS private key - so it is able to sign attestation challenges sent by (remote) host. The host can then verify the signature using the corresponding LMS public key. The LMS public key is provided to the verifying vendor by Winbond.

Rollback Protection

Rollaback protection is a feature that is enforced during fw update, where additionally to swapping active and inactive section halves new version tag is configured. This tag is then used to prevent rollback to previous fw version during next update, so only updates to higher version are allowed. For more details and code see Updates using Symmetric/Asymmetric Cryptography section.

Secure Boot

Secure boot is a feature that ensures only authenticated code is executed during device boot. W77W achieves this with its resiliency features - integrity protected boot section and fallback mechanism. For more details and code see Platform Firmware Resiliency section.
