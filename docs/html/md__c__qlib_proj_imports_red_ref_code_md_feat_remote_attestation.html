Remote Attestation Feature

Direct Attestation

The W77QxxN supports direct establishment of a root of trust without requiring the local MCU to participate in the cryptographic operation. The device can verify a section's digest, make the section cryptographically write-protected, and securely report its status to a remote user over a secure channel.

An authorized remote user first establishes a secure channel directly with the W77QxxN. The user then reads and authenticates the digest of firmware stored in secure flash. The secure channel uses a master key to establish the device's hardware identity, while the firmware digest establishes its software identity. Together, these checks authenticate both identities and provide the basis for a root of trust.

DICE-Like Device Attestation

The W77QxxN provides hardware support for DICE-like attestation and generation of the Compound Device ID (CDI). The CDI is derived from the Unique Device Secret, which establishes the device's hardware identity, and the firmware digest, which establishes its software identity. The device hashes the boot code stored in section 0 to compute the CDI. A user can then establish a session and securely read the CDI from section 0. This operation is allowed only if section 0 is the only section accessed since the last warm reset, through either secure or plain access. This ensures that boot code receives a valid CDI only if its integrity has not been compromised and no other code has been fetched from flash.

LMS-OTS based Device Attestation

The W77QxxN provides hardware support for LMS-OTS attestation and contains a factory-provisioned LMS private key. It can use this key to sign attestation challenges from a local or remote host. The host verifies the signature with the corresponding LMS public key, which Winbond provides to the verifying vendor.
