Atomic firmware update feature

The idea behind atomic update feature is simple: it is done over section (later rollback section) which is split into two halves - active and inactive. New section content (new firmware for example) is written to the inactive part of the section and later cryptographically protected swap command is issued and these halves swap in one atomic operation. Such way enables user to write/download new fw slowly in low power state, while actual update is completed immediately. This "swap" command can be cryptographically protected with both symmetric and asymmetric crypto supported by chip.

Symmetric cryptography based

This is when section configuration command is issued during secure session with the device. So it is just a encrypted spi transaction sent from the local or remote host to the connected W77Q target.Symmetric cypher needs secure session established to the device. This means that each update flow will be different from device to device.

Asymmetric cryptography based

Host produces (maybe offline!) a section configuration string and signes it with the private part of LMS keypair. Section configuration string is then sent with its signature to the W77Q. W77Q uses previously provisioned public part of the LMS keypair to verify the section configuration string and if successful W77Q will execute this configuration command accordingly. Asymmetric cypher does not need session to the device (like symmetric) and actually enables you to send "broadcast update", which is signed by private key.
