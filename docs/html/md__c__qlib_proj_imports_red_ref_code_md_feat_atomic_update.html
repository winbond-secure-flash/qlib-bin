Atomic firmware update feature

Atomic updates use a section, later configured as a rollback section, divided into active and inactive halves. The new firmware is written to the inactive half. Once writing is complete, a cryptographically protected swap command atomically exchanges the two halves. This allows the new firmware to be written gradually, including while the device is in a low-power state, while the final swap completes in a single operation. The swap command can use symmetric or asymmetric cryptographic protection supported by the device.

Symmetric cryptography based

With symmetric cryptography, the section configuration command is issued during a secure session with the device. It is sent from the local or remote host to the connected W77Q target as an encrypted SPI transaction. Because a secure session is required, each update flow is specific to its device.

Asymmetric cryptography based

The host creates a section configuration string, potentially offline, and signs it with the private key of an LMS key pair. The host sends the string and its signature to W77Q. The device verifies the string using the previously provisioned LMS public key and, if verification succeeds, executes the configuration command. Unlike the symmetric method, asymmetric cryptography does not require a secure session with the device and supports broadcast updates signed by the private key.
