Chip Configuration

W77Q/T chip configuration can be done in two main ways: via qlib.h api and via qconf.h api. In most of the case qlib.h is the way to work (also used in sample code).

Via Qlib.h API - Main

This is a main tool to configure your chip, which is also used in sample code - every manufacture flow function will use this code. Note that configuration function may change your flash access policy so if you are working XIP (execution in place) you must carefully arbitrate QLIB and CPU access to flash chip. Via Qconf.h API - Custom

Qconf is a software library that allows W77Q/T chip configuration during bootstrapping it firmware. The idea is to write all configuration on flash during standard loading to flash and then when firmware starts to run it will find the configuration according to magic number, configure the flash and erase that location so that next time configuration does not happen. This module can be used both for W77Q/T development and production support if needed, but requires to RUN firmware on the board. Qconf extends the standard QLIB functionality which is not part of QLIB implementation.

Use-cases

First-time use of W77Q

The first time use of W77Q is a common scenario in both production and development environments. W77Q arrives formatted and configured as a standard flash. To deploy W77Q configuration using Qconf, the user must perform the following 3 steps:

  1. Compile the firmware with Qconf code and Qconf data configuration structure into a single firmware binary (for example named "fw.bin").
  2. Program the "fw.bin" into W77Q using standard flash programming methods.
  3. Perform the first power-up. During this power-up, Qconf programs the configuration into secure W77Q, and then erases its plaintext shadow. On following power-ups Qconf skips the configuration process, as the plaintext configuration no longer exists on the flash. See QCONF_Config for detail.

W77Q recovery (to the standard flash configuration)

In this scenario, the W77Q configuration or code area was corrupted. This can happen, for example, due to power-failure during the above mentioned scenarios. Recovery flow will format chip and configure its legacy access configuration. See QCONF_Recovery section for details.

Qconf configuration structure

Qconf configuration structure, is a single structure that needs to be supplied by the user. This structure includes all W77Q configuration and key values, to be deployed to W77Q, in plaintext. This structure must reside in a read-only flash region. Qconf erases this structure from the flash before applying the read-only configuration. The read-only configuration is necessary to prevent malicious usage of this mechanism.

Qconf integration with target firmware

Qconf is expected to be integrated into the user firmware. The user firmware must execute Qconf on every power-up after QLIB initialization.

For example:

#include qlib.h
#include qconf.h
#define QCONF_CONFIGURATION ((QCONF_T *)0x10300000)
int main(void)
{
QLIB_CONTEXT_T qlibContext;
QLIB_STATUS_RET_CHECK(QLIB_InitLib(&qlibContext));
QLIB_STATUS_RET_CHECK(QLIB_Connect(&qlibContext));
QLIB_STATUS_RET_CHECK(QLIB_InitDevice(&qlibContext));
QLIB_STATUS_RET_CHECK(QCONF_Config(&qlibContext, QCONF_CONFIGURATION));
...
}

Qconf One-Time-Configure (OTC) structure

This structure includes all the configurations that can only be performed once after format or on a factory-formatted device. If the user wants to reprogram this structure with new values, the QCONF_Recovery must be used.

typedef struct
{
KEY_T deviceMasterKey;
KEY_T deviceSecretKey;
KEY_T restrictedKeys[QLIB_NUM_OF_SECTIONS];
KEY_T fullAccessKeys[QLIB_NUM_OF_SECTIONS];
_128BIT suid;
} QCONF_OTC_T;

Qconf configuration structure

Qconf configuration structure includes all configurations, required by QLIB_ConfigDeviceMultiDie function. This structure is used by QCONF_Config to configure or reconfigure W77Q. The configuration in this structure can be reapplied without format, with some exceptions.

For example, one of the exceptions is setting read-only sections. Read-only sections can only be reprogrammed after QCONF_Recovery execution.

typedef struct
{
uint32_t magicWord;
uint64_t flashBaseAddr;
uint32_t numOfDies;
QLIB_FLASH_CONFIG_T flashConfig;
QLIB_DIE_CONFIG_T dieConfig;
QLIB_SECTIONS_CONF_TABLE_T cfgSectionArray[QLIB_MAX_DIES_SUPPORTED];
} QCONF_T;
